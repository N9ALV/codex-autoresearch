Research OS scaffold

Thematic Research OS

A Git-native research workspace shape with Cloudflare used as a read-only publishing layer, not the research execution layer.

Back to home View source docs

Intended shape

local / external agents
  -> write Markdown, YAML, JSON, JSONL, and CSV research outputs
  -> commit those outputs to GitHub branches
  -> review diffs / pull requests
  -> publish the read-only version through Cloudflare
Doctrine

Research stays file-native

Themes organise the work. Companies are expressions. Portfolios are bundles of exposures. Scenario work, evidence quality, and review queues stay explicit in repository files.

Cloudflare role

Read-only publishing

Use Cloudflare to publish reviewed output. Keep writes in Git branches, pull requests, and agent-reviewed commits.

Current setup

No-build placeholder

This repo currently ships a static placeholder surface so Git-synced Cloudflare deploys can succeed before a fuller renderer exists.

Cloudflare publishing path

  1. Keep GitHub as the source of truth for research files.
  2. Use Git-based production and preview deployments.
  3. Gate readers with Cloudflare Access if the research is private.
  4. Keep heavy raw artifacts out of Git until object storage is genuinely needed.
  5. Defer Workers, D1, Vectorize, Queues, and Workflows unless requirements change.

Clean current architecture: local agents do research, GitHub stores research memory, Cloudflare publishes the read-only output, and Access can gate readers if needed.
